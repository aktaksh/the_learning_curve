01 · Fundamentals

What is Linux?

Linux is a Unix-like, open-source operating-system kernel. A complete everyday Linux operating system is a distribution that combines this kernel with user-space tools, libraries, a package manager, services and often a graphical desktop.

🧠

Kernel

The core that controls processes, memory, devices, filesystems and networking.

🧰

User space

Shells, utilities, servers, desktop applications and supporting libraries.

📦

Distribution

A tested combination of kernel, packages, update tools and security policies.

🖥️

Hardware

CPU, RAM, SSD, NIC, GPU and peripheral devices controlled through drivers.

Why Linux is important

Linux powers web servers, enterprise systems, containers, embedded devices, routers, Android-based devices, and supercomputing installations. Its key design ideas are multiuser operation, process isolation, a hierarchical filesystem, small composable command-line utilities, and programmable interfaces.

You type: cat notes.txt
↓

↓
Program requests open/read/write
↓
Linux kernel checks permissions and accesses storage
↓
Terminal displays file contents
Key idea

Linux is not synonymous with Ubuntu or RHEL. Ubuntu and RHEL are distributions; the Linux kernel is the core shared by both.

02 · Architecture

Linux architecture: layers and responsibilities

Linux separates applications from privileged hardware operations. User-space code uses library interfaces and system calls to ask the kernel to perform protected work.

What happens when an application reads a file?

  1. The application calls open(), typically through a C library wrapper.
  2. The kernel validates the path, permissions, mount and descriptor flags.
  3. read() retrieves bytes from page cache or filesystem/storage layers as needed.
  4. The kernel copies accessible data to the process buffer and returns a byte count or an error.
  5. The application processes the bytes; close() releases the file descriptor.

Kernel mode vs user mode

Key idea

The Linux kernel is commonly called monolithic, but it is modular: loadable drivers and other modules can extend the running kernel.

03 · Kernel deep dive

What is the Linux kernel?

The kernel is the privileged program that begins controlling the system during boot and remains active. It arbitrates hardware access and provides abstractions that programs depend on.

⏱️

Scheduling

Chooses which runnable task receives CPU time. Understand priorities, time slices and context switching.

🧩

Memory management

Virtual addresses, page tables, page cache, anonymous mappings, swapping and out-of-memory handling.

💽

Virtual filesystem

Presents files, directories, mounts and device nodes through common APIs.

🔌

Device management

Coordinates drivers, interrupts, bus discovery, DMA and device files.

🌐

Networking

Sockets, IP routing, TCP/UDP, connection tracking and packet filtering.

🛡️

Security

Credentials, permissions, Linux capabilities, LSM hooks, SELinux/AppArmor and isolation.

08 · OS comparison

Linux vs Windows vs macOS

All three are general-purpose operating systems with process scheduling, virtual memory, user permissions, filesystems and network stacks. They differ in kernel design, management interfaces and ecosystems.

Architecture difference: key teaching point

Linux keeps most core subsystems in a single privileged kernel address space, with optional modules. Windows NT uses a hybrid design with a kernel and executive subsystems. macOS uses XNU, combining Mach concepts with BSD components and I/O Kit. These descriptions are architectural simplifications; actual implementations are more nuanced.

Important memory concepts

📄

Paging

Memory is managed in pages; page tables map virtual pages to physical frames.

🧊

Page cache

Frequently accessed file data is cached in memory; Linux may reclaim it.

↔️

Swap

Less-active anonymous pages may be moved to swap when configured.

⚠️

OOM killer

Under severe memory pressure the kernel may terminate selected processes.

🔒

Protection

Page permissions and process isolation limit invalid access.

🧷

A forked child can initially share pages until one side writes to them.

Hands-on experiment: allocate memory

Source code
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
int main(void) {
    size_t bytes = 64UL * 1024 * 1024;
    char *p = malloc(bytes);
    if (!p) { perror("malloc"); return 1; }
    memset(p, 1, bytes);  // Touch pages so memory is committed
    printf("PID=%ld: allocated and touched 64 MiB\n", (long)getpid());
    fflush(stdout);
    sleep(20);             // Inspect with ps / top in a second terminal
    free(p);
    return 0;
}

Source code
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>
#include <errno.h>
int main(void) {
    int fd = open("hello.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (fd == -1) { perror("open"); return 1; }
    const char msg[] = "Hello from Linux system calls\n";
    size_t done = 0, len = sizeof(msg) - 1;
    while (done < len) {
        ssize_t n = write(fd, msg + done, len - done);
        if (n < 0 && errno == EINTR) continue;
        if (n <= 0) { perror("write"); close(fd); return 1; }
        done += (size_t)n;
    }
    if (close(fd) == -1) { perror("close"); return 1; }
    return 0;
}

13 · System administration

Services, systemd and log files

A service is usually a long-running background program. On modern Ubuntu and RHEL, systemd manages service units, dependencies, startup and restarts, while journald collects logs.

Terminal · Ubuntu / RHEL
systemctl status ssh       # Ubuntu: often ssh
systemctl status sshd      # RHEL: often sshd
systemctl list-units --type=service --state=running | head
journalctl -u sshd -n 20 --no-pager   # RHEL example
journalctl -k -n 20 --no-pager
who
uptime
◉ Example output illustrative: values vary by system
● sshd.service - OpenSSH server daemon
   Loaded: loaded (...; enabled)
   Active: active (running) since ...
...
 07:30:00 up 2 days, 5:03,  2 users, load average: 0.06, 0.08, 0.10

Log paths: systemd journal via journalctl; Ubuntu often uses /var/log/syslog and /var/log/auth.log when rsyslog is configured; RHEL-family systems commonly use /var/log/messages and /var/log/secure when traditional text logging is enabled. Do not assume those files exist on every system.

Safe service investigation

  1. Check systemctl status SERVICE and the unit name.
  2. Look for errors using journalctl -u SERVICE -b.
  3. Check whether the service listens: ss -lntp.
  4. Check resource pressure: free -h, df -h, top.
  5. Change configuration only after identifying the cause; back up configuration first.

Good operational habits
